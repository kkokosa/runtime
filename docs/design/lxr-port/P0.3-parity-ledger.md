# P0.3 — Mechanism parity ledger

**One row per reference mechanism.** This document is the artifact P9.1 audits. It is deliberately
rows and tables rather than prose; the narrative, the probes and the evidence behind every entry live
in [`P0.3-oracle-probes.md`](P0.3-oracle-probes.md), which rows cite by section.

**Status of this ledger:** all 26 rows specified. No row is closed — closure requires a .NET
realization, which does not exist yet at P0.3.

| **HEAD** | `0682434` (branch `lxr`) | `304ce69d43aae87de501111fceb8cbd33173a03a` | `…/.cargo/git/checkouts/mmtk-core-91cf05d634be0a1e/304ce69/` |

### 0.2 Field definitions

| field | meaning | completeness rule |
|---|---|---|
| **ID** | stable identifier; P9.1 audits by ID | never reused, never renumbered |
| **Group** | coupled-mechanism set (§1) | mandatory |
| **Declared oracle** | the single oracle that **specifies** the mechanism | mandatory; never blank; `none` is a decision that must carry a reason |
| **Reason** | why that oracle | mandatory |
| **Validation oracle** | where behaviour is **checked**. This is how "specify-from-PLDI, validate-against-HEAD" is expressed without giving a group two declared oracles | mandatory; may equal the declared oracle |
| **Citation** | `<oracle> <hash> <path>:<line>`, resolved at the declared oracle revision **and compiled in the configuration under discussion** — see binding rule 6 | mandatory |
| **Provenance** | `[obs-oracle]` observed executing in a shipped-pair build · `[obs-override]` observed only in a path-override build that never shipped · `[read-only]` never observed executing | mandatory |
| **.NET realization** | what CoreCLR must actually provide. A **design statement, not a measurement** — nothing in P0.3 builds or runs CoreCLR | mandatory |
| **Closure evidence** | the specific artifact P9.1 checks to mark the row closed | mandatory |
| **Status** | `open` · `blocked` · `closed` | mandatory |

### 0.3 Binding rules

1. **Full parity is required.** Approximations and GC-side workarounds are not acceptable substitutes
   for a reference mechanism. A mechanism that cannot be reproduced makes its row **fail**; it does
   not silently degrade.
2. **Every row in a coupled group shares one declared oracle.** Checked mechanically in §4.
3. **Cross-revision comparison is mechanism-to-mechanism, never path-to-path.** A missing path at one
   oracle never means a missing mechanism — at the PLDI oracle there is no `src/plan/lxr/` tree at
   all, and LXR is a compile-time feature configuration of the Immix plan.
4. **Specify-from-PLDI, validate-against-HEAD** governs groups A and B. Probes §6.1 establishes with
   evidence that HEAD is a valid validation oracle for the invariant that matters.
5. **RC width is a designed tunable, not a constant.** Any row touching RC width parameterizes it.
6. **A citation is not evidence unless the code is compiled in the configuration under discussion.**
   A line can sit at the right revision and path, read exactly as the argument needs, and still be
   `#[cfg(…)]`-gated out or commented out — in which case it describes nothing that ran. A citation
   to non-compiled code is permitted only when the row **says so**, and it can never carry a
   behavioural claim. `scripts/verify-ledger.sh` §1c flags gated, commented and empty-bodied
   citations and fails on any that is not acknowledged; §4 enumerates the acknowledged ones. This
   rule exists because an earlier revision of this ledger broke it — row C05 cited two
   `#[cfg(feature = "nogc_no_zeroing")]` functions as the oracles' behaviour, and the check that was
   supposed to catch such things passed, because resolution succeeds for dead code (probes §8).

## 1. Coupled groups

Each group has exactly one declared oracle, shared by every row in it.

| group | scope | declared oracle | validation oracle | reason |
|---|---|---|---|---|
| **A** | RC core | **PLDI** | HEAD | The paper's measured configuration. HEAD relocated the code and changed defaults but the RC algorithm is the same; PLDI is the revision the published results describe. |
| **B** | Field barrier + SATB buffer | **PLDI** | HEAD | Barrier semantics are specified by the revision the paper measured, because the paper's 1.6 % barrier-overhead claim is a claim about *this* barrier. HEAD supplies the **interface model** (`VMSlot`, `Option<ObjectReference>`) — see §3 note B. |
| **C** | Concurrency substrate: buckets, sweeping, safepoints, induced GC, pinning | **HEAD** | HEAD | PLDI's scheduler predates the concurrent-bucket rework; HEAD's is the one that survives contact with a real VM, and HEAD is the only oracle with pinning at all. |
| **D** | Evacuation: mature evac, defrag, remsets, block allocation | **HEAD** | HEAD | HEAD's remset and mature-evacuation structure is materially cleaner and is the direction the codebase took. Probe 2 (probes §5) did **not** move these rows to PLDI — the hypothesis that would have was falsified. |
| **E** | Configuration and plan identity | **HEAD** | HEAD | HEAD selects the plan at **runtime** (`MMTK_PLAN`); PLDI selects it at **compile time** via a feature closure. .NET selects a standalone GC at init time, so HEAD's model is the portable one. |
| **S** | Standalone — not coupled to any group | per row | per row | Each S row states its own oracle and reason. |
| **R** | Risk rows: no reference realization exists on either oracle | **none** | none | Recorded explicitly as `none` with a reason, per §0.2. These are the rows where the reference cannot be an oracle because the reference never did the thing. |

**Group B does not collapse into A.** P0.1 §15 warned it would if `RC_LOCK_BITS` removal turned out to
be semantic. Probes §3.2 resolves that it is not: the log-bit CAS itself linearizes which thread
records the old target, and memory ordering was *strengthened* `Relaxed` → `SeqCst`. A and B stay
separate.

## 3. Rows

### Group A — RC core · declared oracle **PLDI** · validated against **HEAD**

---

**A01 — RC metadata and bit layout**
- **Reason:** RC table geometry is what the paper's space-overhead numbers describe. HEAD relocated
  the constants without changing the layout, so PLDI specifies and HEAD confirms stability.
- **Citation:** PLDI `df8d30a` `src/util/rc.rs:48` (`RC_STRADDLE_LINES`), `:51` (`RC_TABLE`).
- **Validation:** HEAD `304ce69` `src/util/rc.rs:31`, `:34` — same layout, renumbered only.
- **Provenance:** `[obs-oracle]` — executes in both shipped builds on every DaCapo run.
- **.NET realization:** a side metadata region with the same granularity, allocated by the standalone
  GC and not by the EE. CoreCLR has no equivalent today: the card table
  (`src/coreclr/gc/gcinterface.h:81`, `WriteBarrierParameters::card_table`) is a different structure
  with different granularity and must not be conflated with it.
- **Closure evidence:** a metadata-layout unit test asserting table granularity, per-object bit
  offset and total space overhead against the values at the citation.
- **Status:** open

---

**A02 — RC width parameterization (`LOG_REF_COUNT_BITS`)**
- **Reason:** the width is a **designed tunable**, selectable via `lxr_rc_bits_{2,4,8}`; default 2
  bits with `MAX_REF_COUNT == 3`. A port that hardcodes 2 loses a designed degree of freedom.
- **Citation:** PLDI `df8d30a` `src/util/rc.rs:30` (`LOG_REF_COUNT_BITS`), `:43` (`MAX_REF_COUNT`).
- **Validation:** HEAD `304ce69` `src/util/rc.rs:13`, `:26` — same tunable, same default.
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** width is a build-time or init-time constant that propagates to metadata
  geometry, the stuck-count path and the barrier's emitted code. **Parameterize, do not hardcode.**
  Because the barrier is JIT-emitted (B01), the width must be visible to the JIT at the point it
  emits the barrier, not only to the GC.
- **Closure evidence:** the port builds and passes its RC tests at all three widths, and the emitted
  barrier code differs correspondingly.
- **Status:** open

---

**A03 — Straddle-line handling for large objects**
- **Reason:** shares A01's geometry; separated because it is the part most likely to be silently
  dropped in a port and it has no CoreCLR analogue.
- **Citation:** PLDI `df8d30a` `src/util/rc.rs:48` (`RC_STRADDLE_LINES`).
- **Validation:** HEAD `304ce69` `src/util/rc.rs:31`.
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** objects spanning more than one line need their straddling recorded so line
  reclamation is sound. Interacts with R04: CoreCLR's `LOG_MIN_OBJECT_SIZE` and header layout differ
  from OpenJDK's, so the straddle threshold must be re-derived rather than copied.
- **Closure evidence:** a test allocating objects at, just below and just above the line boundary and
  asserting reclamation correctness.
- **Status:** open

---

**A04 — Increment / decrement processing**
- **Reason:** the core of the RC algorithm the paper measures.
- **Citation:** PLDI `df8d30a` `src/util/rc.rs:198` (`ProcessIncs`), `:731` (`ProcessDecs`).
- **Validation:** HEAD `304ce69` `src/plan/lxr/rc.rs:40`, `:669`. Relocated from `util/` into the
  plan; the work-packet structure is preserved.
- **Provenance:** `[obs-oracle]`. Supplementary `[obs-override]` evidence: probes §4 re-instated
  PLDI's zero-RC invariant at the HEAD oracle and ran 48 DaCapo invocations with **zero** violations,
  with a positive control (probes §4.4) showing the assertion site executes ≥ 65 536 times per
  process — so the null result is a real negative rather than an unexercised check.
- **.NET realization:** increment and decrement work packets driven from the barrier's buffers.
  **Carries a mandatory obligation:** the port implements PLDI's invariant
  `old.is_null() || rc::count(old) != 0` as a debug assertion **from the first commit**. This is what
  makes not root-causing PLDI's violation safe (probes §6.1) — the port checks the invariant itself
  rather than inheriting an assumption that it holds.
- **Closure evidence:** the invariant assertion exists, is enabled in checked builds, and a sustained
  load run comparable to DaCapo `-n 5` completes without tripping it. **The closure must include its
  own positive control** — a count proving the assertion executed — since probes §4.1 shows how
  easily an absent check reads as a passing one.
- **Status:** open

---

**A05 — Block and line metadata, block state machine**
- **Reason:** RC reclamation is expressed in terms of block and line state; the state machine is part
  of the RC contract, not of the allocator.
- **Citation:** PLDI `df8d30a` `src/policy/immix/block.rs:14` (`BlockState`), `:85` (`Block`),
  `src/policy/immix/line.rs:18` (`Line`).
- **Validation:** HEAD `304ce69` `src/policy/immix/block.rs:19`, `:74`, `src/policy/immix/line.rs:18`.
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** block and line sizes are re-derived for CoreCLR (R04), not copied. The state
  machine's transitions must be reproduced exactly — a state elided is a reclamation bug that only
  appears under fragmentation.
- **Closure evidence:** a state-transition table test enumerating every transition at the citation
  and asserting the port makes the same ones.
- **Status:** open

### Group B — Field barrier and SATB buffer · declared oracle **PLDI** · validated against **HEAD**

> **Note B — declared oracle versus interface model.** P0.1 §1 recommends HEAD for the field barrier
> while P0.1 §15 places it in a PLDI-semantics coupled set. These do not actually conflict, and the
> ledger resolves them by separating three things: **semantics** are declared from PLDI (the paper's
> 1.6 % barrier-overhead figure is a claim about that barrier); **validation** is against HEAD;
> the **interface model** — `VMSlot`, `Option<ObjectReference>` old targets, `SeqCst` ordering — is
> taken from HEAD, because it is the one that ports. P0.1 §1 itself says "same algorithm", so its
> recommendation was about interface portability, not about semantics.

---

**B01 — Field barrier fast path (JIT-emitted, three tiers)**
- **Reason:** the barrier whose overhead the paper measured. Note B applies.
- **Citation:** PLDI binding `abbdd1d` `openjdk/barriers/mmtkFieldLoggingBarrier.cpp:14` (runtime),
  `:112` (Assembler/interpreter), `:175` (C1), `:278` (C2).
- **Validation:** HEAD binding `0682434` `openjdk/barriers/mmtkFieldBarrier.cpp:29`, `:78`, `:251`,
  `:374` — renamed `record_modified_node` → `object_reference_write_pre`, same three-tier structure.
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** **the barrier must be emitted by RyuJIT, not called as an opaque helper.**
  Both oracles emit it in all three tiers; a helper-call-only port would not reproduce the measured
  overhead and would fail the row under the full-parity rule. CoreCLR's existing write-barrier
  plumbing (`src/coreclr/gc/gcinterface.h:49` `WriteBarrierOp`, `:62` `WriteBarrierParameters`) is
  card-marking-shaped and does not express a log-bit barrier; extending it is a **generic GC-contract
  capability** for which LXR is the first consumer, not the definition.
- **Closure evidence:** disassembly of a JIT-compiled reference store in each tier showing the
  emitted sequence, plus a barrier-overhead measurement against a no-barrier build — the paper's own
  comparison basis (P0.2: 1.6 % is a **geometric** mean against no-barrier Immix, **not** against G1,
  inside a ±3 % noise floor).
- **Status:** open

**B02 — Barrier slow path and the shared decs/SATB buffer**
- **Reason:** the slow path is where RC decrements and SATB entries are buffered; it is the coupling
  point between groups A and B and cannot take a different oracle from B01.
- **Citation:** PLDI `df8d30a` `src/plan/barriers.rs:193` (`FieldLoggingBarrier`), `:313`
  (`fn slow`), `:315–319` (the zero-RC assertion statement; the condition itself is `:316`), `:78`
  (`Barrier::flush` contract).
- **Validation:** HEAD `304ce69` `src/plan/lxr/barrier.rs:32` (`LXRFieldBarrierSemantics`), `:98`
  (`fn slow`), `:157` (`flush_decs_and_satb`). **HEAD has no RC assertion here at all** — this is the
  site probes §4 patched and §4.4 instrumented.
- **Provenance:** `[obs-oracle]`. Supplementary `[obs-override]`: probes §4 and its positive
  control §4.4.
- **.NET realization:** per-thread buffers flushed at safepoints, with the same publication ordering
  as the citation. Carries A04's invariant obligation on the slow path.
- **Closure evidence:** a test that fills, flushes and drains the buffer under contention with the
  invariant assertion enabled.
- **Status:** open

**B03 — Slot log-bit protocol and `RC_LOCK_BITS`**
- **Reason:** the concurrency protocol that decides which thread records a slot's old target.
  Specified from PLDI with a **recorded deviation**: PLDI's dedicated `RC_LOCK_BIT_SPEC` is removed
  at HEAD, and probes §3.2 resolves that this is **not** a semantic weakening — the log-bit CAS
  linearizes the same decision and ordering was strengthened `Relaxed` → `SeqCst`.
- **Citation:** PLDI `df8d30a` `src/plan/barriers.rs:290–298`
  (`log_edge_and_get_old_target`), `:231` (`attempt_to_lock_edge_bailout_if_logged`), `:257`
  (`unlock_edge`), `:268` (`log_and_unlock_edge`).
- **Validation:** HEAD `304ce69` `src/plan/lxr/barrier.rs:86–96` (`log_slot_and_get_old_target`),
  `:60` (`attempt_to_log_field`).
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** **adopt HEAD's protocol, not PLDI's** — single log-bit CAS, `SeqCst`, old
  target loaded before the CAS, no separate lock bit. This is the one row where the declared oracle
  is PLDI but the realization deliberately follows the validation oracle; the deviation is recorded
  here rather than left implicit. `LOG_BYTES_PER_RC_LOCK_BIT` survives at HEAD `304ce69`
  `src/args.rs:117` with no consumer and must **not** be ported.
- **Closure evidence:** a concurrency test asserting exactly one thread observes each slot's old
  target under contention, and that the port emits `SeqCst`-equivalent ordering.
- **Status:** open

---

**B04 — SATB snapshot semantics**
- **Reason:** SATB correctness is a property of the barrier, so it shares group B's oracle.
- **Citation:** PLDI `df8d30a` `src/util/cm.rs:246` (`ProcessModBufSATB`).
- **Validation:** HEAD `304ce69` `src/plan/lxr/cm.rs:328`; a generic equivalent also exists at
  `src/plan/concurrent/concurrent_marking_work.rs:161`, which LXR does **not** use (probes §3.3).
- **Provenance:** `[obs-oracle]`.
- **.NET realization:** snapshot-at-the-beginning marking with the same publication points. CoreCLR
  has no SATB machinery today.
- **Closure evidence:** a test constructing the classic SATB lost-object race and asserting the
  object survives.
- **Status:** open

**B05 — Concurrent marking trace and large-array chunking**
- **Reason:** shares B04's buffer. The `CM_LARGE_ARRAY_OPTIMIZATION` flag flips `true` → `false`
  between oracles, which probes §3.1 resolves as **vestigial**: the optimization became
  unconditional at HEAD, same 1024-element threshold. Not a behavioural difference.
- **Citation:** PLDI `df8d30a` `src/args.rs:9` (`CM_LARGE_ARRAY_OPTIMIZATION`), consumed at
  `src/util/cm.rs:116–126`.
- **Validation:** HEAD `304ce69` `src/plan/lxr/cm.rs:258–266`, `:666–674` — unconditional,
  `ObjectKind::ObjArray(len) if len >= 1024`.
- **Provenance:** `[obs-oracle]` — corrected from P0.1 §18.3's `[obs-override]`; probes §3.3 shows
  the downgrade rested on a file that is present at the oracle and on a dependency LXR does not have.
- **.NET realization:** chunk large reference arrays into separate mark work items at the same
  threshold. Implement it **unconditionally**, per HEAD — do not port the dead flag.
- **Closure evidence:** a marking test over an array well above the threshold asserting it is split
  into multiple work items and that marking terminates correctly.
- **Status:** open

**C05 — Induced-collection policy (`GC.Collect()`)**
- **Reason:** group C (pause-kind selection). **This row exists because of probe 2** — it is the
  resolution of the hsqldb p99 anomaly (probes §5). The two oracles differ here not by degree but in
  kind: HEAD services an induced collection and promotes it to full-heap, PLDI cannot service one at
  all because its handler body is commented out.
- **Citation:** HEAD `304ce69` `src/util/heap/gc_trigger.rs:143` (`handle_user_collection_request`),
  `:149` (the `ignore_system_gc` gate), `:158–161` (sets `user_triggered_collection`, then requests),
  reached from `src/memory_manager.rs:686` via `src/mmtk.rs:436`; then
  `src/plan/lxr/global.rs:614` (`user_triggered` read) and `:643` (promotion to `Pause::Full`). The
  option itself is `src/util/options.rs:869` (`ignore_system_gc`, default `false`).
  PLDI `df8d30a` comparison point: `src/memory_manager.rs:327` → `src/plan/global.rs:353–354` →
  `:590–598`, **whose body is entirely commented out**, so the flag is never set and every consumer
  of it — `src/plan/immix/global.rs:786`, `src/plan/global.rs:699` — sees a constant `false`.
  **Not behaviour citations:** HEAD `304ce69` `src/plan/lxr/global.rs:377–379` and PLDI `df8d30a`
  `src/plan/immix/global.rs:532–534` print `"The request is ignored."` but are under
  `#[cfg(feature = "nogc_no_zeroing")]`, which is enabled in neither oracle's build — **not compiled,
  cited only to record that they are dead** (probes §5.5).
- **Validation:** same. Measured on the shipped HEAD build via the runtime option `MMTK_VERBOSE`
  (HEAD `304ce69` `src/gc_log.rs:7`): 25/25 pauses on hsqldb are `Pause::Full`,
  `cause=UserTriggered`; with `-XX:+DisableExplicitGC` the count is **0** and wall time falls ~39 %.
- **Provenance:** `[obs-oracle]` — observed on the shipped build; `MMTK_VERBOSE` and
  `-XX:+DisableExplicitGC` are runtime switches and do not change the binary.
- **.NET realization:** **a deliberate decision the port must make and measure, not inherit.**
  `GC.Collect()` reaches the GC at `src/coreclr/gc/gcinterface.h:826`
  `IGCHeap::GarbageCollect(int generation, bool low_memory_p, int mode)` and is a documented public
  API with defined semantics. The design space has **three** points (probes §5.7): **(a)** ignore the
  request — HEAD ships exactly this as the runtime option `ignore_system_gc`, so the precedent is
  that it belongs in the *options surface*, not the plan; **(b)** service it as an ordinary
  collection without promoting to full-heap; **(c)** service and promote to full-heap STW, HEAD's
  default, costing ~60 ms on a ~117 MB live set as measured. `GC.Collect()`'s documented semantics
  rule out **(a)** as a *silent default* but not as a *configurable mode*. **(b)** is the point that
  honours the API contract without inheriting the pause and is the expected starting position. The
  `generation` and `mode` parameters must map onto LXR's `Pause` kinds explicitly.
- **Closure evidence:** a documented mapping from `GarbageCollect(generation, mode)` to LXR pause
  kinds, an explicit choice among (a)/(b)/(c) with its reason, and a measurement of
  induced-collection pause time at a live set comparable to the probe's.
- **Status:** open

## 5. What this ledger does not contain

- **Any measurement of CoreCLR.** Every .NET realization is a design statement. Nothing in P0.3
  builds or runs CoreCLR.
- **Benchmark deltas.** The ledger defines which mechanisms later deltas must be attributable to; it
  makes no performance claim. Per P0.2, **application-observed latency is the acceptance signal** and
  pause distribution is a characterization, not a win condition — the paper reports *longer* GC
  pauses than G1 at every percentile in its only comparative pause table.
- **A schedule.** Row order is not implementation order.
- **PLDI's `zero rc count` root cause.** Deliberately out of scope; probes §6.1 records the decision,
  the evidence for it, and the obligation it transfers to row A04.
